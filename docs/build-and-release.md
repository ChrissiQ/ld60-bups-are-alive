# Build and release

How to rebuild the native library, regenerate the motion table, and what the export and the release do. [README.md](../README.md) says how to build and run the game from source; the generated files and their commands are listed in [AGENTS.md](../AGENTS.md#generated-files).

## Native code

The C++ is `LineageStore` and `GpuMemory`. On macOS, rebuild with:

```
cd native && scons platform=macos arch=universal target=template_debug api_version=4.5 -j8
```

and again with `target=template_release`. On Windows the same `scons` command with `platform=windows arch=x86_64` builds the `.dll` files; `native/src/.gdignore` keeps Godot from importing the `.obj` files the compiler leaves there. `native/godot-cpp` must be a clone at `GODOT_CPP_COMMIT` of `.github/workflows/build-native.yml`.

- Say when the C++ changed: the other platforms' libraries come from the release workflow.
- Do not rebuild while headless runs that load the library are in progress.

## The motion table

`scripts/motion_table.gd` is the coarse motion of a bup as a measured table. It is generated by `tools/gen_motion_table.gd` and guarded by hashes. When `motion_table_test` says it is stale, regenerate it.

The table is the average of many runs, one seed each: about 40 s a seed on Apple Silicon, and several hundred seeds for a standard error of about 1e-4 of swim speed per cell. Measure the seeds windowed, then combine them headless:

- Measure with `seeds=<first>-<last> dir=<folder>`. Each run writes a partial file, so machines can share the work.
- Combine with `combine=<folder>`.

The header of the generator has the commands, and the table's own header says how it was made. The measuring runs are windowed and use the GPU for hours in all (see [testing.md](testing.md#windowed-runs)).

A new constant in `SimConstants.build()` must be classified in `MOTION_INPUTS` or `OTHER_CONSTANTS`. The table's hash of `K_SWIM` covers text the game runs through `pool_swim` (see [simulation.md](simulation.md#the-kernels)).

## Export

- **Raw files.** `.cfg` and `.txt` files are exported only when an export preset's `include_filter` names them. `tests/strings_test.gd` checks that every raw file the game reads is covered by each preset.
- **macOS.** The export needs ETC2/ASTC import on (`project.godot`) and is ad-hoc signed, not notarized.

## Release

`.github/workflows/release.yml` builds a release when a `v*` tag is pushed, and only if `.github/workflows/sim-tests.yml` passes in that run. Changing a workflow in `.github/workflows/` changes what builds. No workflow runs on a push to a branch. The simulation tests the release gates on are in [testing.md](testing.md#the-tests-on-a-software-gpu).

The release workflow imports the project with `--import || true`, which hides a shader that fails to import. It then runs `tests/gpu_shaders_test.gd` and stops the release if that fails.
